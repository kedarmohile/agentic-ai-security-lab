WHAT THIS PLATFORM DOES

Test whether an AI agent crosses security boundaries it should not cross.

The objective is to turn agentic-AI security claims into reproducible evidence. The five labs test memory isolation, tool authorization, retrieval poisoning, delegated authority, and credential scope. Start with the built-in deterministic harnesses, then connect the same test pattern to your own application.

THE QUESTION WE ARE ANSWERING
Can this agentic system violate an identity, memory, retrieval, tool, delegation, or credential boundary?
A finding requires evidence from an executed scenario—not a policy statement or model opinion.

TEST YOUR OWN APPLICATION
How the reference labs become security tests for your code
BYO TARGET

Important: the current console executes the built-in deterministic harnesses. It does not automatically scan an arbitrary repository. To test your own code, connect your application to the relevant lab boundary using an adapter. Lab 01 already exposes a direct memory-backend contract; the same adapter pattern is documented for the other boundaries.

MEMORY · LAB 01

Persistent memory

Implement remember(context, key, value) and recall(context, key), then pass your backend to run_memory_isolation_lab().

TOOLS · LAB 02

Privileged tool execution

Map your approval check and tool invocation to the same invariant: no privileged execution without trusted approval bound to the exact action.

RAG · LAB 03

Retrieval pipeline

Inject a benign untrusted document, run a later clean query, and record ingestion → retrieval → directive exposure → downstream influence separately.

IDENTITY · LAB 04/05

Delegation & credentials

Map principal, agent, resource, request, audience, and credential scope into the same exact-binding checks used by the reference harness.
